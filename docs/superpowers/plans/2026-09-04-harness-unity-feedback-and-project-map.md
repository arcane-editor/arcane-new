## Global Constraints

Binding on every task. Reviewers check these.

1. **Prompt-cache stability** (`editor/AI-SPEC.md:69-79`): the system prompt is byte-stable per conversation (decoration frozen in `prompts/frozen-context.ts`); tool membership never flaps mid-session (register per workspace kind, gate inside `execute()`); volatile info goes at the TAIL of the newest user message; the turn governor sends `tool_choice:'none'` and never strips `tools`.
2. **No degraded path reads as success.** Every unknown/skipped/disconnected state is labeled in the text the model reads and in the UI (bridge lost, editor asleep, old package, stream only, unverified).
3. **Deep Modules** (`editor/CLAUDE.md`): import features only through their `index.ts` barrel; `bun run check:modules` enforces it. Feature-internal files are never imported from outside the feature.
4. **Bun tests are DOM-less.** `stores/ai.ts`, the `unity-analyzers`/`unity-input`/`uitoolkit` barrels and anything reaching Monaco or `document` cannot be imported under Bun. Pure logic lives in `services/*.ts` or `utils/*.ts` and is tested directly; runtime feature access happens via dynamic `import()` inside `execute()` or an injected-deps seam (pattern: `preplan-controller.ts:11-27`, `unity-tools/ui-toolkit-tool.ts:88-107`). `bun mock.module` is process-wide: prefer injected deps.
5. **Write-path decorator stack** (`agent-service.ts:363-380`) is fixed: `guardRealPath(editReview(resultDiffs(wrapCs(writeApproval(checkpoint(tool))))))`. Mutate tools declare a top-level `path` (and `content` where diffs apply) so `withCheckpoint`/`withWriteApproval` work with no refactor. Engine-mutate tools use `gated()` from `mutate-tools.ts` with `timeoutMs: Infinity`.
6. **`vendor/agent-loop.ts`** is touched only when a decorator cannot express the change.
7. **`UNITY_CONTEXT`** in `prompts/unity-context.ts` is a template literal: every backtick in added prose must be escaped as `\``.
8. **Escalation integrity:** `turn-telemetry.ts` `isRepairNote` requires a real error count; new passes must never inflate `repairCount` (which drives `send-escalation.ts`).
9. **Server routing is server-side.** The editor sends only facts in `metadata` (`taskType`, `planPhase`, `difficulty`; enum `arcane-server/src/types.ts:85-91`). D1 `app_config` docs override code defaults wherever present — any new doc/field must be optional-safe for deployed docs and documented with the admin `PUT` runbook.
10. **Protocol lockstep:** `PROTOCOL_VERSION` in `editor/src-tauri/src/unity_ipc.rs` equals `Discovery.ProtocolVersion` in `arcane-extension/Editor/Discovery.cs`; both pinned by tests. Every new `.cs` under `arcane-extension/` needs a `.meta` with a fresh GUID. Never edit `editor/unity-bridge/`.
11. **Copy:** sentence case, active voice, plain words; errors say what happened and what to do; no decorative eyebrows/labels. New UI follows existing ai-panel/theme tokens (`App.css` patterns next to the component being cloned).
12. **Every task ships with the tests it lists.** Gates: `cd editor && bun run verify` (tsc + `check:modules` + JS + Rust suites + `verify:intellisense` + `verify:acp`; a `SKIPPED` is NOT a pass) — run the focused tests while iterating and the full gate before the final commit of a task; `cd arcane-server && npm test && npm run check:types`; `cd landing-page && pnpm build` when the admin panel changes. Rust: `cd editor/src-tauri && cargo test`. Known env gotcha: `editor/tooling/unity-eval/run-task.test.ts` can hang under bun on this machine — exclude it from ad-hoc runs if it does; `bun run verify` handles it.
13. **C# compile check** (no Unity runner in CI): against a local Unity install, `SR=/Applications/Unity/Hub/Editor/<ver>/Unity.app/Contents/Resources/Scripting`; `csc -noconfig @rsp` (`-noconfig` on the command line) referencing `$SR/Managed/UnityEngine/*.dll` modules only (not the monolithic facades) + `$SR/NetStandard/ref/2.1.0/netstandard.dll`; tests additionally need `$SR/NetStandard/compat/2.1.0/shims/netfx/mscorlib.dll` + `PackageManager/BuiltInPackages/com.unity.ext.nunit/net40/unity-custom/nunit.framework.dll`.
