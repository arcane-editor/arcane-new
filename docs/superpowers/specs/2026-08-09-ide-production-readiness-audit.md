## Rejected by verifiers (6)

- [perf-memory] Every keystroke ships the entire file contents over Tauri IPC to the LSP, deliberately undebounced — The quoted code is accurate (document-sync.ts:159-184 sends `contentChanges: [{ text: content }]`, workspace.ts:1257-1262 calls it from updateFileContent, which EditorPanel.tsx:283-287 wires to Monaco's onChange), but this is not a defect. Full-document sync is the protocol-sanctioned fallback (TextDocumentSyncKind.Full) and is what many LSP clients ship; nothing here is broken. The cost claim does not hold up: client.ts:367-375 does `JSON.stringify` of the message and a fire-and-forget `invoke('lsp_send', ...)` — the stringify of a 100 KB string is well under a millisecond and the IPC send is async, so at 10 keys/sec this is roughly 1% of a frame budget, not a source of visible caret lag. The heavier per-keystroke work (Monaco materialising the full buffer for `value`) exists regardless of what the LSP layer does. Switching to incremental deltas would be an optimisation, not a bug fix, and it would require building and maintaining a range-delta path that does not exist today.
- [perf-memory] Typing replaces the openFiles array identity, re-rendering TabBar and StatusBar on every keystroke with no memoization anywhere — The store code and the three subscriptions are quoted correctly (workspace.ts:1250-1255; TabBar.tsx:39, StatusBar.tsx:36, EditorPanel.tsx:41), but re-rendering is not the same as a performance defect, and I could not find a cost that matters. TabBar's per-tab work is a Map lookup plus a small filter (getFlatDiagnosticsForUri, stores/ui.ts:33-51, is O(diagnostics for that one file)) over ~15 shallow rows; StatusBar does a single `openFiles.find`; EditorPanel re-renders but does not remount Monaco — `path={modelPath}` is unchanged and @monaco-editor/react no-ops when `value` already matches the model. That is sub-millisecond work sitting behind Monaco's own per-keystroke tokenisation and rendering, which is orders of magnitude larger. Content lives in the store by design, so any edit must invalidate it; the absence of React.memo is a style observation, and the claimed 'measurable input latency that grows with the number of open tabs' is asserted, not demonstrated.
