# UnityIDE 0.4.0

**Working draft, not release-ready.** The approved scope now includes the full
[Rider migration programme](../implementation/unityide-040-rider-migration.md)
and its [capability gates](../implementation/unityide-040-capabilities.json).
The import-focused notes below describe the earlier implementation baseline;
they do not establish completion of the expanded release contract.

UnityIDE now helps Windows and macOS users bring familiar Rider or Visual Studio Code preferences into their Unity workflow.

## Release notes

- Choose Rider, VS Code or UnityIDE defaults on first launch. Existing installations receive an optional setup invitation.
- Review local preferences before importing appearance, supported editor settings and keyboard shortcuts. Choose between detected VS Code profiles or Rider versions, or select a custom configuration folder.
- Use Rider-style dark and light themes and platform-specific keymaps for IntelliJ, Visual Studio, Visual Studio 2022, ReSharper and VS Code workflows.
- Carry over supported custom shortcuts, including two-step sequences. Shortcut hints and macOS menus follow the selected keymap.
- Configure imported typography consistently in normal and diff editors. Missing fonts fall back to available system fonts.
- Change your editor experience, import again or restore the previous configuration from Settings.

Imports read local preference files without changing the source editor. The import report explains unsupported settings and approximations. This release preserves UnityIDE’s existing layout, Unity integration, language services and AI workflows.

The current importer does not yet cover language/workspace settings, Rider .NET formatting profiles, extensions, snippets, custom theme colors or external tool configurations. Required formatting and workspace workflows are tracked by the expanded programme; arbitrary third-party Rider plugins remain outside its scope.

## Implementation and review

The `editor-experience` module exposes editor profiles, key bindings and import previews. Native discovery reads bounded JSONC/XML files; application writes one atomic preference envelope with a revision check and a pre-import restore snapshot. Existing flat settings and cached themes migrate before either app view mounts. Setup ownership uses window leases so remounts and simultaneous launches cannot release another setup flow.

Preferences and resolved shortcuts synchronize across windows. Native macOS accelerators update from the focused window and defer to scoped shortcuts, sequences, find widgets and terminal input. Normal and diff editors share imported typography, indentation and editor preferences. UnityIDE shortcut overrides remain the final layer when importing or switching profiles.

Discovery locations follow the [VS Code settings documentation](https://code.visualstudio.com/docs/configure/settings) and [Rider configuration directory documentation](https://www.jetbrains.com/help/rider/Directories_Used_by_the_IDE_to_Store_Settings_Caches_Plugins_and_Logs.html). Rider themes adapt the [Islands dark/light appearance introduced as the default in 2025.3](https://www.jetbrains.com/rider/whatsnew/2025-3/); preset families follow the [Rider keymap references](https://www.jetbrains.com/help/rider/Reference_Keyboard_Shortcuts_Index.html).
